## Run it locally

Fetch WayneUI's standalone file once, from the pinned 2.0.8 release:

```bash
curl -o public/wayne-ui.php \
  https://wayneui.apps.wayne.edu/v2/releases/2.0.8/wayne-ui.php
```

To move to a newer WayneUI release, change the version in the URL above and run the fetch again.

Install the dependencies and start the server:

```bash
composer install
composer serve
```

`composer serve` sets `APP_ENV=local` for you, so the app signs in with
SESAME's fake driver; a plain `php -S localhost:8000 -t public` would boot
as production instead, because the front controller defaults `APP_ENV` to
production when it is unset.

Open http://localhost:8000. The front controller serves one home page: any
path but `/` answers `404` with a link back home, instead of rendering the
home page again. Locally the app signs in with SESAME's fake driver.

## Checks

The app ships with Pinstripe's coding standard wired in. After
`composer install`:

- `composer lint` checks the code style with Pint, on the per preset.
  `composer fix` applies the fixes instead.
- `composer analyse` runs PHPStan at level 8 over `src/` and `public/`.

`stubs/wayne-ui.php` tells PHPStan about the run-time WayneUI functions,
which come from the fetched `public/wayne-ui.php` and are not in the
template.

`composer ci` runs the test suite, both checks, PROCTOR and
`composer audit`, in that order. A well-kneaded starter passes all of
them.

The GitLab pipeline (`.gitlab-ci.yml`) carries the same checks: the Preflight
components for PROCTOR, the test suite on PHP 8.3, 8.4 and 8.5,
`composer audit`, and one `composer-ci` job that runs `composer install`
followed by `composer ci`, so PROCTOR sees an explicit `composer ci` in the
pipeline.

## Pipeline

Besides the checks above, `.gitlab-ci.yml` runs three gates, all from
Preflight components pinned to one release:

- **Accessibility.** The `a11y-pages` job serves the app on PHP's built-in
  server, signs in with SESAME's fake driver and saves the pages in
  `A11Y_PATHS` (`/`). Preflight's `a11y` job opens each one in Chromium and
  runs axe-core, light and dark, at 320 and 1280 px, at WCAG 2.2 AA (the ADA
  Title II rule names 2.1 AA, which 2.2 AA includes). A violation fails the
  pipeline. Add each page you build to `A11Y_PATHS` and to the a11y
  include's `pages`. Automated checks find only part of the problems, so try
  each page with a keyboard and a screen reader too.
- **Bill of materials.** Preflight's `sbom` job keeps `sbom.cdx.json`, a
  CycloneDX list of the Composer packages `composer.lock` installs, for 30
  days. When the next advisory lands, search these files to see whether this
  app has the package.
- **Secrets.** Preflight's `secret-detection` job runs Gitleaks over the
  repository and fails on anything shaped like a credential (redacted in the
  log).

This app deploys with a Citadel Quick Update, so its pipeline holds no
deploy credential. When you add a deploy job, extend `.deploy`: it never
runs for a merge request and runs only on a protected branch or tag. The
file cannot hold the rest, so set these in GitLab before the first
credential goes in:

1. Protect `main` and your release tags (Settings > Repository > Protected
   branches, Protected tags), so only maintainers push or tag them.
2. Store each deploy credential as a CI/CD variable with **Protect
   variable** on and visibility **Masked** or **Masked and hidden**
   (Settings > CI/CD > Variables). GitLab gives protected variables only to
   pipelines on protected branches and tags. Masking keeps the value out of
   job logs; it does not stop code in the pipeline from reading it.
3. Never put a credential in `.gitlab-ci.yml`, in a component's `inputs` or
   in a file in the repository.
4. Keep the job token allowlist on (Settings > CI/CD > Job token
   permissions). When another project's pipeline must fetch from this one,
   add that project by name.
5. Read a merge request from a fork before you run its pipeline in this
   project: code in a fork can try to read this project's variables.
6. Prefer the deploy target's own secret store (on Citadel, the app's
   environment settings) to a CI variable for anything long-lived.

A starter this well guarded still needs someone to lock the bakery at night.

## Sign-in

The app signs in with SESAME. In development (when `APP_ENV` is not
`production`) it uses the fake driver. It signs you in as `jdoe` with no
password. In production it uses the cas driver. The cas driver needs two
variables.

- `SESAME_CAS_URL`: the CAS server URL.
- `SESAME_SERVICE_URL`: this app's public URL. It is the URL the CAS server
  sends the user back to.

Set both in the environment before you deploy. A starter without its flour
will not rise.

The cas driver checks each ticket with the CAS server through Guzzle (10
second timeout, no redirects, TLS verification on), and it only accepts a
ticket for a sign-in this browser started: before it sends you to CAS it
leaves a marker in the session, so `public/index.php` hands SESAME and the
driver the same `NativeSession`.

## Running off Citadel

The app reads its platform facts from the environment, so it runs on
Citadel, OpenShift, Coolify or raw Docker. Mix these to taste: a good
starter rises on its own.

| Variable | What it does | Example |
| --- | --- | --- |
| `APP_ENV` | The environment; `production` turns off error display and the fake driver | `production` |
| `HELMET_PROXIES` | Comma-separated proxy addresses to trust; empty trusts nothing | `172.18.0.1` |
| `LOG_FILE` | Where PHP errors go; unset means stderr | `/var/log/app/error.log` |
| `SESSION_SAVE_HANDLER` | The session store; unset keeps PHP's default | `redis` |
| `SESSION_SAVE_PATH` | The session store's address; unset keeps PHP's default | `tcp://redis:6379` |
| `SESAME_SESSION_IDLE_MINUTES` | Minutes of inactivity before SESAME signs out; unset keeps the default | `30` |
| `SESAME_SESSION_ABSOLUTE_MINUTES` | Minutes after login before SESAME signs out regardless; unset keeps the default | `480` |

On Citadel the deploy files from Squire run at release time: `build.sh`
prepares the image, `deployments/001-first-release.sh` is the one-time
first-release hook, and `scripts/release.sh` is the idempotent release
script. They come from Squire's checked copy, so Squire owns them. Refresh
them with Sourdough, not by hand. Elsewhere, set the env vars above and
build `.squire/portable.Dockerfile`, Squire's portable image: it runs as a
non-root user in group 0 on port 8080, for OpenShift, Coolify and raw
Docker.
