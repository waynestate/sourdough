# {{app_name}}

A Wayne State application, generated by Sourdough (raw PHP with a Vue front end). PHP signs you in and answers JSON; Vue,
built by Vite, draws the page with WayneUI's Vue components.

## Run it locally

Install the dependencies:

```bash
composer install
npm install
```

Then either build the front end once and serve it:

```bash
npm run build
composer serve
```

or, while you work on the Vue side, run the Vite dev server next to PHP (two terminals) for hot reload:

```bash
npm run dev
composer serve
```

Open http://localhost:8000 either way. `npm run dev` writes `public/hot` and removes it when it stops;
while that file exists, `src/Vite.php` loads the app from the dev server instead of `public/build`.
Commit `package-lock.json` after the first `npm install`: the release script installs from it.

`composer serve` sets `APP_ENV=local` for you, so the app signs in with
SESAME's fake driver; a plain `php -S localhost:8000 -t public` would boot
as production instead, because the front controller defaults `APP_ENV` to
production when it is unset.

## How it fits together

- `public/index.php` is the front controller. HELMET, the session and SESAME boot exactly as in the raw PHP shape.
  Paths under `/api/` answer JSON (`/api/me` returns the signed-in user, or `401`); `/` sends the page that loads
  the Vue app; any other path sends the same page with a `404`, and Vue says the page does not exist.
- `src/Vite.php` prints the script and stylesheet tags, from the dev server or from `public/build/manifest.json`,
  each with HELMET's CSP nonce. While the dev server runs it also adds it to the Content-Security-Policy.
- `resources/js/App.vue` is the page. It imports WayneUI's components from `@waynestate/wayne-ui-vue`, and
  `resources/css/app.css` pulls WayneUI's built, layered stylesheet from `@waynestate/wayne-ui-css`.

Add an endpoint as one more `case` in the `/api/` switch in `public/index.php`. Anything that writes should be a
`POST` that checks the request's origin: turn on HELMET's `csrf` option in `helmet_boot()` when you add the first one.
Everything an endpoint returns reaches the browser, and so does every `VITE_` variable: keep secrets on the PHP side.

## Checks

The app ships with Pinstripe's coding standard wired in. After
`composer install`:

- `composer lint` checks the code style with Pint, on the per preset.
  `composer fix` applies the fixes instead.
- `composer analyse` runs PHPStan at level 8 over `src/` and `public/`.

`composer ci` runs the test suite (including `tests/ViteTest.php`), both
checks, PROCTOR and `composer audit`, in that order. A well-kneaded starter
passes all of them.

The GitLab pipeline (`.gitlab-ci.yml`) carries the same checks: the Preflight
components for PROCTOR, the test suite on PHP 8.3, 8.4 and 8.5,
`composer audit`, one `composer-ci` job that runs `composer install`
followed by `composer ci`, and a `frontend` job that runs `npm run build`.

## Sign-in

The app signs in with SESAME. In development (when `APP_ENV` is not
`production`) it uses the fake driver. It signs you in as `jdoe` with no
password. In production it uses the cas driver. The cas driver needs two
variables.

- `SESAME_CAS_URL`: the CAS server URL.
- `SESAME_SERVICE_URL`: this app's public URL. It is the URL the CAS server
  sends the user back to.

Set both in the environment before you deploy. A starter without its flour
will not rise.

## Health check

HELMET answers the load balancer's ping at `/up` with `200 ok`, without
touching the database.

## Running off Citadel

The app reads its platform facts from the environment, so it runs on
Citadel, OpenShift, Coolify or raw Docker. Mix these to taste: a good
starter rises on its own.

| Variable | What it does | Example |
| --- | --- | --- |
| `APP_ENV` | The environment; `production` turns off error display, the fake driver and the Vite dev server | `production` |
| `HELMET_PROXIES` | Comma-separated proxy addresses to trust; empty trusts nothing | `172.18.0.1` |
| `LOG_FILE` | Where PHP errors go; unset means stderr | `/var/log/app/error.log` |
| `SESSION_SAVE_HANDLER` | The session store; unset keeps PHP's default | `redis` |
| `SESSION_SAVE_PATH` | The session store's address; unset keeps PHP's default | `tcp://redis:6379` |
| `SESAME_SESSION_IDLE_MINUTES` | Minutes of inactivity before SESAME signs out; unset keeps the default | `30` |
| `SESAME_SESSION_ABSOLUTE_MINUTES` | Minutes after login before SESAME signs out regardless; unset keeps the default | `480` |

On Citadel the deploy files from Squire run at release time: `build.sh`
prepares the image, `deployments/001-first-release.sh` is the one-time
first-release hook, and `scripts/release.sh` is the idempotent release
script. The release script runs `npm ci` and `npm run build` when it finds
`package-lock.json`, so `public/build` is built on the server and stays out
of git. The deploy files come from Squire's checked copy, so Squire owns
them. Refresh them with Sourdough, not by hand.
