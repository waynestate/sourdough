# Changelog[#](https://sourdough.apps.wayne.edu/docs/changelog.html#changelog)

All notable changes to Sourdough are recorded here. The format follows Keep a Changelog; the project follows Semantic Versioning once 1.0 is out.

## Unreleased[#](https://sourdough.apps.wayne.edu/docs/changelog.html#unreleased)

- Changed: the front-end templates floor Vite at ^6.4.1, the CVE-2025-62522 fix line, and ignore \*.local, where Vite keeps local secrets (BEST_PRACTICES 4.12).
- Changed: every app shape and Sourdough's own CI pin Preflight 0.4.0 (87d9b6f; the proctor job clones the full history, so the override-approver check can read git blame).
- Added: WORKER_HEARTBEAT_MAX_AGE=0 turns the scheduler heartbeat check off, so an app that runs no scheduler still answers 200 on /ready.
- Added: new bakes take the PHP floor from CREED's `policy.json` (BEST_PRACTICES 4.2, now `Enforced`). Sourdough requires `waynestate/creed` `^0.1` and reads its policy, or the file `SOURDOUGH_POLICY` names. As of the policy's `refreshed_on`, the floor is the oldest PHP line still supported 365 days later, bounded by the Laravel major's PHP range on the Laravel shapes. It is written into `composer.json` (`require.php`, `config.platform.php`), the `.gitlab-ci.yml` matrix and the README on all five shapes. A policy that cannot be read bakes on the pinned fallback (`^8.3`, tested on 8.3, 8.4 and 8.5) and says so. Today's output is unchanged. `sourdough new` prints a `PHP:` line, and `--dry-run --json` gains a `php` object. `tests/PhpFloorTest.php` changes the policy's floor and checks every shape.
- Added: every shape has an owner role, a support status and a sunset path (BEST_PRACTICES 3.7, now `Checked`). The new "Support and sunset" guide (`docs/guides/support.md`) is the policy (the window lengths are a proposal), and `resources/shapes.json` holds the fields. `sourdough new` prints a `Support:` line with the framework's end of security from CREED, and `--dry-run --json` gains `support`. A deprecated shape prints a notice on every `new` and `feed`, and feeding a removed shape names its replacement. `tests/ShapeSupportTest.php` holds the catalog to the rules.
- Changed: the Laravel shapes' `config/helmet.php` holds only the app's `policy_path` override, and HELMET's provider merges the rest from the package (BEST_PRACTICES 3.6). The old 403-line copy had fallen behind HELMET: it had no Playbook lookup for `HELMET_PRESET`, and no `session.secure`, metrics storage or warn settings. Feed replaces an unchanged copy, and an edited one gets a conflict to keep your own keys. 3.6 lists the template code still waiting for a library, starting with `config/sesame.php`, which skips Playbook's CAS URL and defaults CAS to protocol 3.0.
- Added: every shape's pipeline carries three gates from Preflight 0.3.1 (BEST_PRACTICES 4.15, 6.4 and 6.5, now `Enforced`; 3 practices remain `Not yet`). Accessibility: an `a11y-pages` job boots the app with SESAME's fake driver and saves its pages (`/`, plus `/dashboard` signed in on the Laravel shapes), and the `a11y` component checks them at WCAG 2.2 AA, blocking. Bill of materials: the `sbom` component keeps `sbom.cdx.json`, and the front-end shapes' `frontend` job adds `sbom-npm.cdx.json` from CycloneDX's npm tool. Secrets: the `secret-detection` component runs Gitleaks, and a hidden `.deploy` template keeps any future deploy job off merge requests and on protected refs. Each generated README's new "Pipeline" section lists the GitLab settings a file cannot hold. New `tests/TemplateCiGatesTest.php`, plus `testBakedPipelineCarriesTheCiGates` in every generator test, holds all five shapes to it.
- Added: the Laravel + Blade + Vue islands shape has its own `.gitlab-ci.yml` with a `frontend` job (it used to inherit the Blade pipeline, which never built its front end).
- Added: the Laravel shapes (Blade, Blade with Vue, Inertia) ship Laravel Boost ^2.10 in require-dev, the stack's guidelines in `.ai/guidelines/wayne-state.md` (managed) and starter rules in `.ai/rules/` (seeded), a `.gitignore` block for what `boost:install` writes (`/.mcp.json`, `/boost.json`, `/AGENTS.md`, `/CLAUDE.md`, `/.claude/skills/`, `/.junie/`; `.agents/` stays tracked for Booster), a guarded `composer boost-update` appended to Laravel's `post-update-cmd`, a README section, and `tests/Feature/BoostDevOnlyTest.php`, which fails when Boost leaves require-dev or packages-dev. `tests/BoostWiringTest.php` holds the wiring; BEST_PRACTICES 2.3 is `Enforced`.
- Changed: a Laravel bake drops the skeleton's `CLAUDE.md` and `AGENTS.md` when they hold only Laravel's Boost bootstrap block (`boost:install` writes them again); a file with other guidance is kept and stays in git. The overlay merge appends `pre-` and `post-` Composer hooks to the skeleton's instead of replacing them, and a new `gitignore-additions.txt` control file adds ignore lines once.
- Changed: `--no-advisor` removes only ADVISOR's own `.mcp.json` line; the Laravel shapes keep `/.mcp.json` ignored for Boost.
- Changed: BEST_PRACTICES.md marks 18 practices with their true status on main (exit codes, output, kit features off, Boost, the Laravel window, MySQL 5.6, env config, VITE\_ secrets, Composer in CI, npm ci, Vite on localhost, the PHP matrix, APP_KEY, CRLF, Docker images, three OSes, templates as archives, boring startup); 9 remain Not yet.
- Added: every app with a front end ships an `.npmrc` with a one-day npm cooldown (`min-release-age=1`), a `.nvmrc` and `engines.node >=22` in its `package.json`; the shapes without a front end get none of it (BEST_PRACTICES 4.9 and 4.11 are `Checked` by the generator tests).
- Changed: every image in the baked CI files is pinned by digest: composer:2.10.3 now carries its multi-arch list digest, like the Node image already did.

## 0.1.7 (2026-11-07)[#](https://sourdough.apps.wayne.edu/docs/changelog.html#0-1-7-2026-11-07)

### Added[#](https://sourdough.apps.wayne.edu/docs/changelog.html#added-2)

- Added: `sourdough feed` brings template updates into an app made with `sourdough new`, without clobbering what the app changed (ADR-0014, decision 4). It bakes the app's shape again with the answers in its manifest and goes file by file: files the template did not change are left alone, untouched managed files take the new version, files both sides changed are three-way merged by `git merge-file`, same-line changes get git's conflict markers (`<<<<<<< app` ... `>>>>>>> sourdough <version>`) and never a silent overwrite, new template files are added, dropped ones are removed only when untouched, binary files are never merged (the template's copy lands as `<file>.sourdough-new`), and seeded files are never touched. The base for a merge is found by its manifest hash, in `.sourdough/base/` (the template's version of each changed managed file, kept by the previous feed) or anywhere in the app's git history; with no base, both versions are marked. Feed then moves the manifest to the new base. It runs only on a clean git tree, refuses while the last feed's markers are unresolved, and refuses a manifest from a newer Sourdough. `--dry-run` prints the plan and writes nothing (exit `0` fresh, `1` feeding would change files, so it works as a CI gate), `--json` prints the plan for machines; a real feed exits `0` fed cleanly, `1` fed with conflicts, `2` tool error. It needs git and nothing else. Every shape is covered by `tests/FeedCommandTest.php`, and the smoke gate now checks that a fresh bake of each shape has nothing to feed.
- Added: the proof harness, `scripts/proof.sh` (Linux, macOS) and `scripts/proof.ps1` (Windows), and the Proof page (`docs/reference/proof.md`) with its dated Last run table. In Docker, one after another, it runs the smoke gate on all five shapes and on every Laravel shape with `--sail` and with `--docker` (eleven runs), and feeds a bake of the last release (read from this changelog) forward in each. It writes `proof-out/last-run.md`, a summary and every step log, and exits `1` when any run fails. A GitLab `proof` job runs it by hand or on a schedule that sets `SOURDOUGH_PROOF` to `1`, never on a push, and keeps the results as an artifact. `tests/ProofHarnessTest.php` keeps the two scripts, the gate, the CI job and the table listing the same runs.
- Added: the smoke gate checks more of every loaf. Right after the bake, `sourdough manifest --check` must be clean. Every shape runs its own suite as its own step (the count goes in the proof table) and `composer proctor`. The Laravel shapes now boot too, on Laravel's own router: `/` must answer with the shape's home page (the Blade page, the built Vue islands, or the Inertia `Home` page), `/dashboard` after SESAME's fake sign-in, `/nope` 404 and `/up` 200; the raw shape's `/` must carry its home page in WayneUI's shell. A second argument, `--sail` or `--docker`, proves a Laravel shape's oven (the scaffold's files, install, suite, PROCTOR), and `SMOKE_FEED_FROM=<version>` bakes that release from Packagist and feeds it forward. `scripts/smoke-shape.ps1` takes `-Oven` and `-FeedFrom` to match.
- Added: the Laravel shapes ship skeleton feature tests (`tests/Feature/SkeletonTest.php`, Pest, next to the starter's example tests): `/up` answers 200, the home page answers 200 for a guest (the Blade page, the built Vue island, or the Inertia `Home` component), a guest at `/dashboard` goes to the sign-in flow, the dashboard renders for a signed-in user after SESAME's fake sign-in (with the islands view's `data-vue-island="counter"` island and the Inertia `Dashboard` component checked too), a missing page answers 404, and `UserResolver::refreshUser()` turns a stored user array back into the `User` by username, or `null` when the username no longer exists. Each baked Laravel suite grows from two tests to nine, and the proof table quotes the new counts.

### Fixed[#](https://sourdough.apps.wayne.edu/docs/changelog.html#fixed-2)

- Fixed: the Inertia shape's progress bar wears its styles again. Inertia injects them in an inline `<style>`, and HELMET's CSP admits one only with the request's nonce, so the browser refused it on every page ("Refused to apply inline style") and the bar ran unstyled. `resources/js/app.ts` now reads the nonce from the pre-paint script's `nonce` property and hands it to Inertia 3's new `nonce` option, which stamps it on everything Inertia injects; no CSP is loosened.
- Fixed: the Laravel templates' `UserResolver` lists its interfaces in Pint's order (`RefreshesUser` before `UserResolverContract`), so a freshly baked app passes its own `pint --test` on the first run instead of failing `composer ci`.

## 0.1.0 (2026-10-29)[#](https://sourdough.apps.wayne.edu/docs/changelog.html#0-1-0-2026-10-29)

### Added[#](https://sourdough.apps.wayne.edu/docs/changelog.html#added-8)

- The raw app now installs SQUIRE's deploy files from a checked copy at `templates/squire/`: `build.sh`, `deployments/001-first-release.sh`, `scripts/release.sh`, `scripts/parity.sh`, `scripts/parity.ps1`, `health.php`, `public/up.php`, `docker-compose.squire.yml`, `.env.squire.example`, and the `.squire/` build context. SQUIRE owns them; Sourdough copies them as-is and records them in the manifest.
- `composer squire-copy:check`: verify that `templates/squire/` still matches a fresh export from the SQUIRE checkout (`SQUIRE_PATH`, default `/squire`). Skips with exit 0 when no checkout is mounted.

### Changed[#](https://sourdough.apps.wayne.edu/docs/changelog.html#changed-8)

- Refreshed the SQUIRE template copy in `templates/squire/` from e66f07b to 2a893c0: the Vue layer's `.npmrc` and `docker-compose.squire.yml` joined the batch. Fresh flour, same recipe.

### Removed[#](https://sourdough.apps.wayne.edu/docs/changelog.html#removed-1)

- The raw template's own `deployments/release.sh` and `deployments/release.ps1`; the release steps now come from SQUIRE.
